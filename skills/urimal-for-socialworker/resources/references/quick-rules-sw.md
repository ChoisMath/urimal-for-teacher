# Quick Rules — 사회복지 Monolith Fast Path 전용 (v2.1)

`urimal-monolith` 에이전트가 한 콜에서 사회복지 문서의 탐지·윤문·자체검증을 끝내기 위해 사용하는 슬림 룰북. 본진 `sw-tell-taxonomy.md`(14개 카테고리)·`urimal-source.md`(한덕연 선생님 36항목)·`ai-tell-taxonomy.md`(v2.0)에서 **사회복지 문서에 자주 등장하는 S1·S2 핵심**만 추렸다.

**원칙:** 정의 1줄 + 처방 1줄. 예문 생략. 본진 ID와 1:1 매칭.

**Do-NOT (탐지·윤문 모두 제외):**
- 고유명사·기관명·사업명·인명 (예: ○○구청, △△복지관, 김□□ 어르신)
- 수치·날짜·단위·금액·기간 (예: 1,200만 원, 2026-05-15, 4주)
- 큰따옴표 안 직접 인용
- 법률·고시·규정 조문 (예: 「사회복지사업법」 제33조)
- 학술 개념어·전문 용어 (예: 임파워먼트, 사례관리, 슈퍼비전)
- 영어 약어 업계 표준 (예: ICF, MOU, KPI)

**과윤문 가드:** 변경률 30% 초과 = 경고, 50% 초과 = 강제 중단·롤백.

## SW. 사회복지 도메인 핵심 (한덕연 우리말 36항목 기반)

### SW-01. 호응·짝 오류

| ID | 패턴 | 심각도 | 처방 |
|---|---|---|---|
| SW-01-A | 주어-술어 불일치 | S1 | 맥락에 맞는 술어로 수정 |
| SW-01-B | 부사-동사 불일치 (예: "일주일간 시작합니다") | S2 | "일주일간의 ~을 시작합니다" |
| SW-01-C | "~부터 ~까지" 짝 누락 (예: "기획·진행·평가까지") | S2 | "기획부터 평가까지" |
| SW-01-D | 높임말 호응 불일치 ("이야기를" vs "말씀을") | S1 | 호응 단계 통일 |
| SW-01-E | 주어 누락으로 행위자 혼동 | S2 | 주어 명시 |

## 자체검증 체크리스트 (monolith 윤문 후 자가 점검)

윤문 직후 5초 내에 다음을 자체 점검한다. 한 항목이라도 위반이면 해당 edit 롤백.

1. **고유명사·기관명·사업명·수치·날짜·인용 100% 보존**: 원문 대비 한 글자도 다르지 않은가
2. **변경률 30% 이하**: 50% 초과 시 작업 중단·롤백
3. **장르 유지**: 계획서가 에세이·블로그체로 변하지 않았는가
4. **register 보존**: 원문 격식체면 결과도 격식체. 평어체로 떨어뜨리지 않는다
5. **잔존 S1 패턴 0건**: SW-01-A·SW-05-B·SW-09-A·SW-09-E·SW-12-G·SW-13-A·SW-13-H·SW-14 전체, A-7·A-8·A-16·C-5·C-10·C-11·D-1·D-2·D-4·D-6·H-1·H-3·I-1·J-2 핵심 S1이 남아있지 않은가
6. **차별·시혜·권위적 표현 0건**: SW-14 전체 잔존 시 결정적 실패 — 즉시 재윤문
7. **인공 표현 자제**: 원문에 없던 비유·수사·문학적 표현을 임의로 추가하지 않았는가

위반 시: edit 롤백 → 다시 윤문 → 재점검. 자체 루프 최대 1회. 이상 미해결이면 결과를 그대로 출력하되 final.md 끝 `<!-- HUMANIZE-SUMMARY -->` 블록에 "자가검증 미통과 항목 N건" 표기.

## 등급 기준 (자가 채점)

- **A**: S1 잔존 0, S2 잔존 2 이하, 변경률 10~25%, 자체검증 7항 모두 통과
- **B**: S1 잔존 0, S2 잔존 4 이하, 자체검증 6항 이상 통과
- **C**: S1 잔존 1~2 또는 자체검증 5항 이하 통과 — 사용자에게 strict 모드(6+1인 파이프라인) 권고
- **D**: S1 잔존 3+ 또는 변경률 50% 초과 또는 SW-14 잔존 — 작업 중단·사람 검토
