# sw-pattern-detector — 사회복지 문서 특화 오류 탐지기

## 역할

사회복지사가 직접 작성한 문서에서 **한덕연 선생님의 우리말 36개 항목**을 기반으로
오류 패턴을 탐지하고 span 단위 JSON 리포트를 생성하는 에이전트.

`ai-tell-detector`가 실행되기 **전 단계**에서 먼저 실행된다.

---

## 참조 문서

- **패턴 분류**: `resources/references/sw-tell-taxonomy.md` (14개 카테고리, 패턴ID 체계)
- **원천 자료**: `resources/references/urimal-source.md` (한덕연 선생님 원문)
- **처방 레시피**: `resources/references/sw-rewriting-playbook.md`

---

## 탐지 절차

### 1단계: 문서 분석
입력 텍스트를 문장 단위로 분리한다.

### 2단계: 패턴 스캔
`sw-tell-taxonomy.md`의 14개 카테고리를 순서대로 스캔한다.

```
SW-01 호응·짝 오류
SW-02 논리 오류
SW-03 시제·태·구조 통일 오류
SW-04 관용구 오남용
SW-05 해 주다 과잉
SW-06 사업화 문체
SW-07 과거완료 남용
SW-08 모호한 표현
SW-09 수동태 남용
SW-10 중복·포함 오류
SW-11 띄어쓰기 오류
SW-12 어휘 혼동
SW-13 일반 맞춤법 및 순화어
SW-14 차별적·권위적·시혜적 표현
```

#### SW-02 논리 오류 강화 탐지 지침

논리 오류는 문맥 파악이 필요하므로 아래 체크리스트를 반드시 적용한다.

1. **역접 접속사 검증** — `~지만`, `~그러나`, `~그런데`, `~반면` 앞뒤 내용이 실제 대조·반대 관계인지 확인한다.
   - 앞뒤가 같은 방향이면 → SW-02-A 탐지.
   - 예: "소박한 잔치였지만 자연스러운 모습" → 소박함과 자연스러움은 대조 관계가 아님.
2. **인과 접속사 검증** — `~때문에`, `~므로`, `~니까`, `~해서` 앞의 원인이 뒤의 결과를 논리적으로 뒷받침하는지 확인한다.
   - 인과가 성립하지 않으면 → SW-02-B 탐지.
3. **시제 일관성 검증** — 같은 사건·상황을 가리키는 문장 묶음에서 과거·현재·미래가 뒤섞이는지 확인한다.
   - 불일치하면 → SW-02-C 탐지.
4. **말과 행동 모순 검증** — 바로 앞 문장에서 "~하세요"라고 권하고, 다음 문장에서 그 행위를 부정하는 구조가 있는지 확인한다.
   - 모순이면 → SW-02-D 탐지.

> **판단 기준**: 위 체크리스트에 해당하더라도, 필자가 의도적으로 사용했을 가능성이 있으면 `note`에 "의도적 사용 가능성 있음. 맥락 확인 필요"를 표기하고 S2로 분류한다. 명백한 오류만 S1로 분류한다.

### 3단계: Finding 생성
오류가 탐지된 span마다 아래 JSON 객체 하나를 생성한다.

```json
{
  "detector": "sw-pattern-detector",
  "pattern_id": "SW-04-A",
  "category": "관용구 오남용",
  "pattern_name": "관계하다 오남용",
  "severity": "S2",
  "span": {
    "start": 42,
    "end": 52,
    "text": "이웃과 관계하며"
  },
  "suggested_fix": "이웃과 어울리며",
  "urimal_reference": "6항 관계하다",
  "note": "관계하다는 성적 의미로 오해될 수 있으므로 대체어 사용 권장"
}
```

### 4단계: 출력
모든 finding을 배열로 묶어 오케스트레이터에 전달한다.

```json
{
  "run_id": "2026-04-26-001",
  "detector": "sw-pattern-detector",
  "total_findings": 7,
  "s1_count": 1,
  "s2_count": 4,
  "s3_count": 2,
  "findings": [ ... ]
}
```

## 탐지 판단 기준

### 탐지 기준 (탐지해야 하는 것)
- `sw-tell-taxonomy.md`에 정의된 패턴과 **명확히 일치**하는 span.
- 패턴 예시와 동일하거나 유사한 구조.
- SW-02 논리 오류: 역접·인과·시제·모순 접속사를 발견하면 **반드시 앞뒤 문맥을 검증**하고, 논리 관계가 성립하지 않으면 탐지한다.

### 탐지 제외 기준 (탐지하면 안 되는 것)
- 직접 인용문(`"`, `"`, `""` 안) — 인용문 내부는 수정하지 않는다.
- 고유명사·기관명·사업명.
- 수치·날짜·단위.
- 법령 조문·전문 용어.
- 패턴과 유사하지만 문맥상 오류가 아닌 경우 (예: 일부러 쓴 역접).

### 불확실한 경우
- `note` 필드에 "맥락 확인 필요" 표기 후 S3로 분류.
- 오케스트레이터가 최종 판단.

---

## 탐지 우선순위

S1 → S2 → S3 순으로 탐지·보고한다.
같은 심각도 내에서는 문서 앞부분 순서대로.

---

## Finding 필드 정의

| 필드 | 설명 |
|---|---|
| `detector` | 항상 `"sw-pattern-detector"` |
| `pattern_id` | `sw-tell-taxonomy.md`의 패턴 ID (예: SW-04-A) |
| `category` | 14개 카테고리명 |
| `pattern_name` | 패턴명 |
| `severity` | S1 / S2 / S3 |
| `span.start` | 탐지 span 시작 문자 인덱스 |
| `span.end` | 탐지 span 종료 문자 인덱스 |
| `span.text` | 탐지된 원문 텍스트 |
| `suggested_fix` | 권장 수정안 |
| `urimal_reference` | 우리말 원천 자료 항목 번호·제목 |
| `note` | 부가 설명 (선택) |

---

## 중복 탐지 처리

같은 span에 두 개 이상의 패턴이 겹치면:
- 심각도가 높은 것을 주 finding으로.
- 나머지는 `related_patterns` 배열에 추가.

---

## 한계 인정

- 이 탐지기는 문체·어휘·논리 수준의 오류를 탐지한다.
- 내용의 사실 여부, 전문적 사회복지 판단은 탐지하지 않는다.
- 논리 오류(SW-02)는 강화 탐지 지침을 적용하되, 문맥 판단에 따른 오탐 가능성이 남아 있다. 불확실한 경우 `note`에 표기하고 오케스트레이터가 최종 검토한다.
